# Solution

## Architecture

Use Astro static output as the application boundary. Astro file-based pages own routing, one Astro layout owns document metadata and the shared shell, and local JSON is imported directly during the build. Keep Vue integration only for `v-blur-text.vue` and `v-prism-background.vue`, because those components require browser lifecycle, animation state, or WebGL. Convert every presentational Vue component to Astro so it emits HTML without hydration.

This approach is preferred over wrapping the existing SPA in Astro because it removes Vue Router, Pinia, the global application, and page-wide hydration. It is preferred over rewriting the two interactive effects in vanilla JavaScript because their current Vue implementations already handle lifecycle cleanup and reduced motion correctly.

## Project Configuration

1. Replace `vite.config.ts` with `astro.config.ts`.
   - Set `site` to `https://ibrahimturan.dev` and keep static output.
   - Add `@astrojs/vue` for the two Vue islands.
   - Add Tailwind CSS 4 through `@tailwindcss/vite` in Astro's Vite configuration.
   - Add `@vite-pwa/astro` with the existing `autoUpdate` registration, manifest metadata, colors, and 192px/512px/maskable icon entries.
   - Preserve the `@` alias through TypeScript/Astro resolution.
2. Update `package.json` scripts to use `astro dev`, `astro check && astro build`, `astro preview`, Astro-aware ESLint, and Astro-aware Prettier.
3. Add Astro, Vue, PWA, type-check, ESLint, and Prettier integrations. Remove Vue Router, Pinia, Vue TypeScript configuration, `vue-tsc`, and unused application dependencies.
4. Replace the Vue TypeScript project references with `astro/tsconfigs/strict`, include Astro files, and add `src/env.d.ts` for Astro and PWA client types.
5. Move retained Vue test configuration from `vite.config.ts` to `vitest.config.ts`.
6. Extend `eslint.config.js` with `eslint-plugin-astro` recommended configuration and update `.prettierrc.json` with `prettier-plugin-astro`.

## Pages, Layout, and Metadata

1. Replace `src/pages/home.page.vue` with `src/pages/index.astro` so `/` is generated by Astro.
2. Replace `src/pages/colors.page.vue` with `src/pages/colors.astro` so `/colors` is generated by Astro.
3. Replace `src/layouts/default.layout.vue` with `src/layouts/default.layout.astro`.
   - Render `<html lang="en" data-theme="ibrahimturan-dark">`, the global stylesheet, one skip link, one `main`, and the shared footer.
   - Accept title, description, and path props.
   - Emit canonical, Open Graph, Twitter, favicon, manifest, theme-color, and analytics markup.
   - Register the generated service worker through `virtual:pwa-register` with immediate automatic updates.
4. Move home-only CSS from the Vue page into the Astro page unchanged.
5. Import `src/data/userInfo.json` directly in the page and components. Do not create replacement state management.

## Components

1. Convert all non-interactive atoms, molecules, and organisms from `.vue` to `.astro`, retaining kebab-case names, public props, slots, semantic markup, and full literal Tailwind classes.
2. Replace Vue computed class arrays with build-time maps and Astro `class:list` values.
3. Replace `router-link` behavior in `v-button` with standard anchors because Astro owns navigation.
4. Replace the global icon plugin with `v-icon.astro`.
   - Import the existing named icon definitions directly from `oh-vue-icons`.
   - Map the known social and technology names to package-owned SVG definitions.
   - Render the trusted SVG path data statically with accessible labels and current-color styling.
5. Keep `v-blur-text.vue` and `v-prism-background.vue` unchanged as the only Vue components.
6. In the migrated `hero-section.astro`, hydrate blur text and prism explicitly with visibility-based client directives. No presentational component receives a client directive.
7. Preserve the active home page hierarchy, experience timeline, technology groups, footer, social links, responsive classes, reduced-motion rules, and print rules.

## Cleanup

1. Remove `src/main.ts`, `src/app.vue`, `index.html`, `src/router/`, `src/stores/`, and `src/plugins/` after their consumers are migrated.
2. Remove replaced `.vue` components and obsolete Vue Test Utils suites that assert those removed implementations.
3. Keep the existing tests for `v-blur-text.vue` and `v-prism-background.vue`; do not add new unit tests.
4. Update `README.md` structure and commands from Vue SPA terminology to Astro static-site terminology.
5. Update `.impeccable/live/config.json` only if its current Vite entry points refer to removed files.

## Verification

1. Run Prettier, ESLint, Astro type checking, retained Vue tests, and the production build.
2. Serve `dist/` through Astro preview and request `/` and `/colors`.
3. Inspect generated HTML for portfolio content, title, description, canonical URL, Open Graph data, manifest link, and service-worker registration assets.
4. Use a browser at desktop and mobile viewport sizes to verify both routes, navigation anchors, responsive layout, icons, fonts, styling, and accessibility landmarks.
5. Verify the web manifest and service worker are reachable from the production preview and that the manifest contains standard and maskable icons.
